## Bridge and chain configs

Rhino.fi has two configurations:

- The **bridge config** lists every chain and token available for bridging.
- The **swap tokens config** lists the tokens available for bridge and swap, by chain.

You can fetch them with these SDK calls:

```typescript
// Bridge config
const bridgeConfigResult = await sdk.api.config.bridge()
// Tokens available for swapping, by chain
const swapTokensResult = await sdk.api.config.swapTokens()
// Shortcut to fetch both configs in one call
const allConfigsResult = await sdk.api.config.all()
```

[Learn about the bridge API](/sdk/bridge-api).

If no error occurs, the bridge config looks like this:

```typescript

  ETHEREUM: {
    name: "Ethereum",
    type: "EVM",
    networkId: "1",
    contractAddress: "0xbca3039a18c0d2f2f84ba8a028c67290bc045afa",
    multicallContractAddress: "0x0dbBD1bB03Ed63AE2beA0Ce892567884dffb70a5",
    confirmationBlocks: 5,
    avgBlockTime: 12,
    nativeTokenName: "ETH",
    nativeTokenDecimals: 18,
    nativeTokenSafeguard: 0.008,
    blockExplorer: "https://etherscan.io",
    rpc: "https://...",
    site: "https://ethereum.org",
    status: "enabled",
    tokens: {
      ETH: {
        token: "ETH",
        address: "0x0000000000000000000000000000000000000000",
        decimals: 18
      },
      USDC: {
        token: "USDC",
        address: "0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48",
        decimals: 6
      },
      USDT: {
        token: "USDT",
        address: "0xdac17f958d2ee523a2206206994597c13d831ec7",

    },
    gasBoostEnabled: false
  },
  SOLANA: {
    // same format as above
  },
  // Every supported chain has an entry here
}
```

The whole object corresponds to the `BridgeConfig` type exported by the SDK. Each key is a chain, and each value is that chain's config (the `ChainConfig` type). Each entry in a chain config's `tokens` field is a `TokenConfig`.

Many SDK functions take the `BridgeConfig`, or a specific `ChainConfig` or `TokenConfig`, as parameters. For most advanced use cases, fetch the bridge config first.

## Chain adapters

The SDK takes a modular approach: all blockchain interactions are handled by chain adapters. When you use one of the bridge functions, you always pass in a chain adapter that matches the origin chain.

Chain adapters handle:

- Fetching balances
- Checking and setting token allowances
- Making a deposit to a bridge contract
- Estimating the gas fees for a bridge transaction (optional)

Resources:

- [More about chain adapters](/sdk/chain-adapters/overview)
- [How to implement custom chain adapters](/sdk/chain-adapters/custom-chain-adapters)

## Supported chains and tokens

Bridge functions often take chains or tokens as `string` parameters, so the SDK provides lists of supported chains and tokens to avoid magic strings:

```typescript
import { SupportedChains, SupportedTokens } from '@rhino.fi/sdk'

const chainIn = SupportedChains.ETHEREUM
const chainOut = SupportedChains.SOLANA
const token = SupportedTokens.USDT
```

These lists are generated when the SDK is released, so they can fall out of sync with the bridge config if Rhino.fi adds a chain or token, or temporarily suspends one.

<Warning>
  To show users a list of available chains or tokens, always use a freshly fetched bridge config. Don't rely on these hard-coded lists for that.
</Warning>

`SupportedTokens` doesn't include swap tokens, as they change too often for a static list.

See [Supported chains and tokens](/get-started/supported-chains) for the chains and tokens available for Smart Deposit Addresses.

## Error handling

Many SDK functions return an object with nullable `data` and `error` fields instead of throwing. Checking that one is defined narrows the other to non-nullable in the opposite code path. Errors are always a discriminated union with a `_tag` or `type` field as the discriminator. Some error types include extra fields with details about the error.

For example, an error when generating a user quote could be:

```typescript
{
  _tag: 'WithdrawLimitReached',
  token: 'USDT',
  chain: 'ETHEREUM',
  receiveAmount: '5000',
  maxWithdrawAmount: '1000'
}
```

Amounts in errors are decimal strings in whole token units, as everywhere in the API. See [Errors](/api-integration/core-concepts#errors) for the common error names and what to do about them.
